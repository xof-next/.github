## About

XOF is an independent engineering organization. We design and build software foundations: backend systems, developer tools, real-time communication, and protocol engineering. Our work prioritizes measurable efficiency, interoperability, security, and systems that run reliably across environments.

**Bahasa Indonesia:** XOF adalah organisasi engineering independen yang membangun fondasi perangkat lunak: sistem backend, developer tools, komunikasi real-time, dan rekayasa protokol, dengan mengutamakan efisiensi yang terukur, interoperabilitas, keamanan, dan kesiapan lintas lingkungan.

## Journey

| Period | Milestone |
|:--|:--|
| 2017–2020 | **Xcraft**: early experiments in bots and automation |
| 2020 | **Transition**: the Xcraft phase ended, and the experience became groundwork for engineering work |
| 2021–2024 | **Foundation**: backend and data flow, developer tooling, npm packages, networking optimization, and protocol exploration |
| 2025–2026 | **Public ecosystem**: QUIC and HTTP/3 packages, HTTP framework, HTTP client, and HTML tooling |

## Focus areas

| Area | What we work on |
|:--|:--|
| **Backend engineering** | APIs, service architecture, data flow, and maintainable backend components |
| **Real-time systems** | Responsive communication, event flow, and streaming data for interactive use cases |
| **Protocol engineering** | Transport, connection management, multiplexed streams, and service-to-service communication |
| **Distributed services** | Cross-region service design with attention to routing, consistency, and resilience |
| **Security by design** | Transport encryption, authentication, access control, and data protection built into the architecture |
| **Developer experience** | Packages, libraries, APIs, and tooling that make integration clear and consistent |

## Engineering principles

- **Efficiency with evidence:** optimization is guided by measurement, bottlenecks, and real needs.
- **Security as a foundation:** data and communication protection are considered from the design stage.
- **Resilient by architecture:** systems are designed to handle network variation and component failure.
- **Clarity for developers:** tooling and documentation should reduce friction, not add it.
